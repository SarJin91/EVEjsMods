# Shared Store Performance Fix

Workaround for an EveJS 261126.2 bug. Saving the `structures` table rewrites
every structure in one SQLite trigger. Without table statistics the query
planner picks a join order that rescans the whole JSON document once per
structure, so the save grows with the square of the structure count:
about 3 minutes for 819 structures. That blocks the database long enough for
the server to lose its persistence lease at startup.

After each writable game database open (`sqliteStore.init`, main thread and
persistence worker) the mod stores one row in `sqlite_stat1` for the
`(parent_id, ordinal)` index of `structure_records`, reloads the statistics
and checks the trigger's query plans with `EXPLAIN QUERY PLAN`. With the row
the save is linear (about 4 s for 819 structures, 14 s for 3276).

- No data, table, index or trigger of EveJS is changed. The startup check
  (`startupSharedStore.js --check`) does not look at statistics.
- When the plan generated by EveJS is already good without statistics, the
  mod deletes its own row and logs `VENDOR_FIXED`. The mod can then be removed.
- Log lines start with `[sharedStorePerfFix]`: `PINNED` on the first start,
  nothing on later starts, `DRIFT` or `PLAN_NOT_FIXED` (error) when the fix
  cannot work. Then the mod does nothing and EveJS runs as vanilla.

## Sovereignty mirror saves

At scheduler startup EveJS repairs the structure record of every sovereignty
hub (`reconcileSovereigntyCampaigns` → `syncSovereigntyStructureRuntime` →
`structureState.upsertStructureRecord`). Each mirror record carries
`stateStartedAt` set to the current time, so every call rewrites the whole
`structures` table, a few hundred times in the first minutes.

The mod wraps `structureState.upsertStructureRecord` for records with
`devFlags.sovereigntyMirror === true` only:

- When the stored record has the same `state`, the old `stateStartedAt` is kept.
- When the normalized record is then equal to the stored one, the call returns
  `{ success: true, data }` without a write.
- Any other change (state, position, owner, entosis, flags) is written as
  before. Durable saves and structures with an active self-destruct receipt
  are always written.

Counters: `globalThis[Symbol.for("evejs.sharedStorePerfFix.mirrorSkip")]`
(`skipped`, `written`, `keptStartedAt`, `errors`, `drift`).

## Settings

| Key (environment) | settings.json | Default | Meaning |
|---|---|---|---|
| `EVEJS_SSPF_ENABLED` | `enabled` | `1` | Off = the mod reads and writes nothing |
| `EVEJS_SSPF_NO_INSTALL` | - | empty | Any value skips installing the hook |
| `EVEJS_SSPF_PIN_ROWS` | `pinRows` | `100000` | Row count in the statistic |
| `EVEJS_SSPF_BUSY_TIMEOUT_MS` | `busyTimeoutMs` | `0` | Lock wait of writing connections, 0 = server default |
| `EVEJS_SSPF_MIRROR_SKIP` | `mirrorSkip` | `1` | Off = every sovereignty mirror save rewrites the table |

## Offline tool

Run with the server stopped (apply and remove refuse while a persistence
owner holds a live lease):

```text
node mods/sharedStorePerfFix/tools/plannerPin.js --status <gamestore.sqlite>
node mods/sharedStorePerfFix/tools/plannerPin.js --apply  <gamestore.sqlite>
node mods/sharedStorePerfFix/tools/plannerPin.js --remove <gamestore.sqlite>
```

Removing the mod leaves the row in place, which keeps the good plan.
`--remove` restores vanilla completely.

## Docker

`docker/entrypoint.sh` loads `/app/mods/sharedStorePerfFix/loader.js` first,
before any mod that opens the game store.
